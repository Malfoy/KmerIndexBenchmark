# Benchmark protocol

## Comparisons

The default comparison is k=31, target individual-key FPR2^-8, dense versus
minimizer indexing. Profiles also cover2^-4 and2^-16. All native tools use the
current CPU affinity; runs are serial and each selected size completes before
growth. Existing exact-tool measurements may be reused across precision profiles
only when binary, dataset, queries, thread count, resource policy and native
settings match. Such reuse is explicit in the result.

Zindex uses native OCM31 with windows spanning49 bases (19 consecutive31mers).
Its frozen source uses the historical CLI: `--k 49 --minimizer-size 31`, with spaces
between flags and values in actual recorded commands. This is equivalent to the
new upstream CLI's `--k 31 --window 19`. Dense mode uses `--k 31`. There is no findere.

For the other tools, the kit reproduces the commands actually used in the local
campaigns. COBS, compressed kmindex, Fulgor, MetaGraph and Themisto receive
canonical random31mer representatives generated by SimdMinimizers2.3.1 through
the pinned Rust FASTA utility. Kaminari also receives these representatives in
this experiment; its internal minimizer length remains the calibrated30.
Historical ATB8 Raptor uses native prepare/layout/build at31/49. Other Raptor
minimizer campaigns use the supplied representatives and native window31.
These choices are encoded in the adapters, not inferred from a tool's name.

Shared external minimizer extraction is reported separately and excluded from
native index construction time. Native OCM/Raptor extraction is inside native
construction/query timing. Generated representative FASTAs can be much larger
than the compressed source genomes; they are shared at one collection size
and removed after that size finishes unless `--keep-prepared` is selected.

## Accuracy and fixed settings

Probabilistic settings were selected on a standalone approximately5Mb genome,
with separate calibration and held-out probes, and then frozen across collection
sizes. Kaminari used two identical reference columns, checking the first column.
The included profiles retain the measured standalone accuracy/provenance where
available. They do not tune parameters on a larger collection or run calibration
trials automatically. Exact methods require no FPR tuning.

kmindex uses its frozen single-hash matrix size, z=0, and native compression
(block8MiB, level6, no reordering). If no empirical frozen case exists for a
precision/mode, the parameter record explicitly marks the analytical size; it
must not be described as a completed paper calibration. Such unfrozen native
cases are not launched by the paper-profile runner. The three exact tools
are unaffected by fingerprint width.

Standalone FPR/FNR values describe individual key/reference membership. Positive
source misses in the long-query performance workload are recorded independently
and do not turn a successful execution into a failure. Random long negatives
are not treated as an exact oracle for every emitted native minimizer key.

## Queries

Positive queries are retained fragments of indexed genomes in both orientations.
The retained negative workloads are uniform DNA queries from the original
experiment. Each original query is1kb, with a0.8 matching threshold. Dense and
native minimizer tools process the original records. For external minimizers,
each selected31mer is queried atomically with the same query threshold; its
native result is mapped back to the original parent and the fraction of matching
representatives is evaluated against0.8. Original-read source misses are reported.

Fresh runs execute **one** positive and **one** negative native process. The
compressed query FASTA is read and Linux `mincore` verifies100% resident pages
before starting the timer. Native decompression, parsing, extraction, index
loading and output are all inside wall time. The index cache is not forcibly
flushed, and input prewarming time is excluded. There are no automatic query
repetitions. Some historical comparator curves in the bundled paper data used
medians of three runs; fresh single-run measurements must be identified as such.

## Resource accounting and cleanup

GNU time reports wall, user/system CPU and peak RSS for each native stage.
Construction CPU/wall are summed across stages; construction RSS is the maximum
stage RSS. A separate sampled simultaneous native-process-tree RSS is retained.
Query RAM is max(positive peak RSS, negative peak RSS), never their sum.

Final index size is logical final-artifact bytes. Temporary and combined
index+temporary allocated disk bytes are sampled during native construction at
30s intervals: these peaks are lower bounds, not exact maxima. gzip source
inputs and query output archives are excluded from native construction scratch.
Completed Zindex cell/recovery staging, Raptor preparations and kmindex native
intermediates are classified separately from final artifacts.

The explicit default48GB native RSS budget is an RSS guard, not a virtual-memory
limit. A2GB free-disk reserve protects the workspace. kmindex's preflight includes
its real uncompressed matrix dimensions. A pre-native disk deferral is not an
execution failure and may be reconsidered on a later user invocation. Changing
resource budgets is recorded; index/FPR parameters are never silently retuned.

The kit keeps inputs, queries, commands, logs, metrics, manifests and compressed
query outputs. Each tested index and its own scratch are removed after the case.
Failed construction/query logs remain, and completed construction metrics are
saved before queries. Nothing outside the owning case's payload is cleaned.
